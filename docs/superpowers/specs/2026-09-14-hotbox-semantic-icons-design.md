# 热盒与菜单统一图标

用户明确要求：热盒和菜单每个功能的左侧都有图标，使用统一的 Blender 图标风格。范围是 AxisMeld 的 Space 主热盒、Views/QWER及子环、组件/创建/建模热盒、普通列表和级联（含Object组合菜单）。继续已确认的布局与输入规则，不扩展到全部上游Blender窗口。

## 显示契约

- 复用本构建内置静态Blender图标，不引入位图、下载素材或混合emoji。按稳定command/id集中解析语义，同一功能在不同入口和Recent保持相同图标；无精确图标的条目使用恰当的功能类目图标。
- 所有非分隔的功能、目录、设置与灰显缺口都获得语义图标。图标在文字左侧，随UI scale缩放并遵循原生主题/选中/禁用显示；菜单级联箭头仍在右侧。
- radio/checkbox是独立状态，不可被新增语义图标替换。普通列表按“状态（适用时）→功能图标→文字”排列，保留可识别的选中状态。参数格、翻页和返回已是图标控件，保留原职责与独立命中，不叠加重复图标。
- 语义图标占20逻辑像素（16图标+留白），有状态时另保留状态槽。测量和绘制共享同一规则；不得用固定字符长度估宽。
- 五行热盒保留24行高、Views当前中心宽度及实际净间距。新增图标通过按钮向外增宽容纳，不压缩Views、中心取消区或内侧留白；窄窗口按既有规则夹紧/分页/不支持处理。精简Views标签也必须测量图标。

## 实现边界

现有 `view3d_axismeld_hotbox_draw.cc` 仅映射少量图标，并对direction_label清空图标、对native_menu用状态覆盖语义。`interface_menu_overlay.cc` 目录分支又强制ICON_NONE。此次统一修正映射、测量和两条绘制分支；不触碰命令分发、JSON目录与输入生命周期。

图标解析留在editor层的独立纯函数，避免向无UI依赖的bf_axismeld引入图标头。不往1403节点JSON添加icon字段，保持256KiB预算与配置schema。菜单overlay仅扩展可选状态图标表示，仍复用Blender原生绘制，不注册新的弹窗handler或独立输入区。

## 验证与交付

先取得旧安装缺语义图标的实际截图RED。新增原生测试检查真实catalog非分隔图标覆盖、代表功能映射、别名/Recent一致及结构控件边界；图标必须来自内置静态枚举。实际GUI确认主热盒、Views、QWER、组件、创建、Object与普通级联图标可见，radio/checkbox和参数格独立，1x/2x清晰且无重叠。

图标占宽影响实际几何，必须同实例比较Views与QWER/组件/创建/建模的实际内缘、取消区和外延，并回归列表/Options/释放。构建至新的独立安装目录，保留旧三个安装及运行中的未保存窗口。更新统一人工清单和图文交付记录；用户人工测试仍暂缓。
