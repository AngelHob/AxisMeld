# 建模交互优先对齐：热盒、快捷键与菜单

日期：2026-09-11。状态：用户已批准并要求开始执行；M1 工具热盒有界适配已安装、人工待测，
M2/M3 尚未完成。具体交付状态见各批次验收记录，不由本规格推定。

## 1. 本轮目标与优先级

先让建模工作流中的常用热盒、快捷键和菜单遵循 Maya 2026 的组织与操作习惯，
再开发缺失的功能。公共发行基线与个人改键继续分离。

范围为 3D View 的 Object / Mesh Edit，以及直接服务这些上下文的选择、变换、
对象与组件编辑、网格显示和建模工具入口。曲线、曲面、变形目录保留原有位置，
其相关原生能力按同一规则归类，不在首批重写这些子系统。

- **UV 整体后置**：编辑器、快捷键、热盒、选择、工具和算法都不提前改造；
  只保留既有 UV 占位和长期接口规划，不以“先做交互”为由启动 UV 工作。
- 动画、绑定、雕刻、渲染、合成等独立工作流不纳入本轮全面改键。
- Global 物体缩放差异继续搁置，不因统一变换菜单而重新开发。
- 已知极窄视口遮挡保留缺陷记录，不排在常用热盒前面；若阻断本轮目标交互，
  只修复使该交互可用所必需的范围，不把已知失败包装成回归通过。

## 2. 三类功能的处理规则

| 分类 | 快捷键 | 热盒与菜单 | 实现边界 |
|---|---|---|---|
| 两边一致或相似、Blender 已有可用能力 | 在建模上下文直接替换成核实过的 Maya 默认键位 | 放到对应 Maya 路径，共用语义命令 | 调用 Blender 原生操作；相似但有差异的标记 adapted，不等待算法完全等价 |
| Maya 有、Blender 尚无可用对应能力 | 记录目标键位与按下/释放关系；不绑定假实现 | 在对应位置放不可执行占位，说明未实现并关联计划编号 | 本轮不为了填满菜单而实现专有能力；名称相似不构成映射证据 |
| Blender 特有能力 | 不凭空发明 Maya 默认键位；保留无冲突原生键位 | 按 Maya 的功能分类加入原有菜单组，必要时在该组尾部用分隔线区分扩展项 | 保留 Blender 名称和语义，不统一塞入“Other”或复制整套 Blender 菜单 |

“直接替换”仍需确认作用对象、组件、参数入口、结束/取消与撤销；它不是绕过
冲突检查，也不是把有近似命令的功能重新开发一遍。差异记录不应成为拒绝接入
正常原生能力的理由，但会破坏数据或明显执行另一种任务的近似项不能启用。

未实现功能占位与当前上下文不可用的真实命令必须可区分。前者无执行命令，
不写 Recent，不产生撤销项；后者保留真实身份，换到有效上下文后可用。

## 3. 采用的集成方案

继续使用现有“命令注册 → 上下文适配 → 热盒/菜单/键位入口”结构，扩展必要的
按住键和鼠标组合处理。菜单内容与布局分离，按内容选择容器，不按层级硬套形状。

不采用全局替换 Blender 所有编辑器键位的方案：这会误伤 UV、文本输入和其他
不在本轮的模式，并增加上游合并冲突。也不采用只换热盒标签的方案：它无法统一
实际键盘、菜单和工具入口的行为。

### 3.1 同一个命令，多种入口

- 快捷键、Space 热盒目录、工具 marking 菜单和普通菜单引用同一稳定 command ID。
- 适配器决定可用条件、原生执行入口和差异；界面不各自拼接不同操作。
- 一次性执行、切换持续工具、交互式操作分别登记，不把“切换工具”和“立即执行”混用。
- 失败保持原生状态；Recent 继续只依据原生 FINISHED 和既有可重放规则记录，
  CANCELLED / PASS_THROUGH 不记录，不扩大成全应用历史。
- 网格编辑沿用原生撤销。几何修改必须验证一次撤销恢复，不给通用 dispatcher 整体加 UNDO。

### 3.2 统一容器与事件行为

- 常用方向动作放紧凑、同组等宽的 marking 热盒；设置、选项和深目录用 Blender 原生菜单。
- 普通子菜单贴父入口，父级保持显示；子菜单活动时背景无关热盒不参与命中。
- 复用现有拖曳引导线、中心安全留白、紧凑二级间距、父子返回和取消规则。
- 一级继续使用个人外观设置及默认 75% 不透明度；二级及以下原生样式且完全不透明。
- 同一手势只允许一次提交；释放拥有鼠标键、释放触发键、Esc、失焦与区域失效均需清理状态。
- 不把 W/E/R 的单次选工具延迟到长按超时；不把键盘自动重复当作多次打开菜单。
- 不假定所有入口都是“按住某键后自动显示”：逐一核对 Maya 的鼠标组合和 press/release 路由。
  Space 的松键关闭规则不能盲目复制到所有工具 marking 入口。
- Alt 导航、轴点选后中键拖动、单/四视图及正交旋转锁定均为必须保持的回归项。

### 3.3 配置兼容

- Maya 2026 默认、工作室、个人、会话与 Blender 用户键位编辑继续分层。
- 旧 schema-1 的单次 PRESS 绑定保持有效。复合手势若需要新结构，使用明确版本的
  独立扩展并提供旧文件读取测试，不让原解析器静默接受未知字段。
- 按键和其释放事件成对路由；改键或禁用入口后，不留下原按键的残余 release 监听。
- 已核实但未实现的 Maya 键位，只在适用建模上下文按既有预留机制处理，
  不在整个应用吞键，不覆盖用户显式配置，不自动禁用第三方插件。
- 冲突报告必须列出命令、上下文和来源；有意义的全局快捷键冲突不能用删除检查来绕过。

## 4. 开发顺序

| 批次 | 目标 | 完成边界 |
|---|---|---|
| M1 常用工具热盒 | Q/W/E/R 的点按与按住相关菜单；优先形成选择、移动、旋转、缩放的一致调用链 | 核实 Maya 默认触发和方位，已有能力接入，缺失项占位；不一次性开发吸附/枢轴缺失能力 |
| M2 上下文建模热盒 | 对象/组件右键及建模相关修饰键 marking 入口 | 按 Object、点、边、面和空白处核对内容与命中；不拦截 Alt 导航，不污染其他模式 |
| M3 建模菜单与快捷键覆盖 | Select / Modify / Edit / Create / Display、Mesh / Edit Mesh / Mesh Tools / Mesh Display，再整理相关 Curves / Surfaces / Deform 原生项 | 建立逐项映射，分小批直接改键/接入原生功能；Maya 缺失项留计划，Blender 独有项归类 |

批次是主线顺序，不要求把所有热盒都完成后才给其中已接入命令配置快捷键；
每一个命令的键位、菜单和热盒入口应在同一小批完成。已实现的 Space 热盒随每批回归。
常用菜单的具体方向和条目先由 Maya 默认实现核实，不由本规格凭记忆发明。

## 5. 菜单归类准则

| 目录 | 内容归属（作为分类原则，不代表对应命令已接入） |
|---|---|
| Select | 集合选择、扩展/收缩、相似选择、对象/组件选择类型 |
| Modify | 工具、坐标与枢轴设置、变换相关操作；Apply Transform 不标为完全等价 Freeze |
| Edit / Create / Display | 编辑和复制 / 创建 / 对象显示与隐藏，保持类别分离 |
| Mesh | 对象级网格组织、整体处理与拓扑转换 |
| Edit Mesh | 挤出、倒角、桥接、合并、分离等组件操作 |
| Mesh Tools | 持续交互的切割、焊接、环线和滑移工具 |
| Mesh Display | 法线、平滑/锐边与网格显示数据 |
| Curves / Surfaces / Deform | 相应数据/变形能力；按功能归类，不直接罗列全部修改器 |

同类 Blender 扩展项优先进入现有对应子组，避免抢占已核实的 Maya 快速划选方向。
目录允许同时含可执行项和未实现占位，不能因为部分内容未实现就永久禁用整个目录。

## 6. 当前证据与首批预检

本次阅读核实的现状：

- `scripts/modules/axismeld/keymap.py`：建模键位转换限定非 modal 建模映射，
  视图命令与对象/网格命令分流；其余编辑器沿用上游生成结果。
- `commands.py`：Q/W/E/R 目前是 PRESS 工具命令；D/X/C/V/J/F12/1/2/3 为预留输入。
- `profiles.py`：现有配置只接受 PRESS，不能通过仅添加 RELEASE 配置完成长按菜单。
- `hotbox_catalog.py`：Space 菜单已有选择、变换、视图和设置命令；建模行主要目录仍禁用。
- 本机原版 Maya 2026 `scripts/startup/hotkeySetup.mel:319-321`：Q、Shift+Q、Alt+Q
  分别关联选择相关的按下与释放命令；`:341-346`：W/E/R 分别关联工具 marking 的按下/释放。
  这些证据只确定绑定身份，不能单独证明鼠标键、延时和方位。
- 同文件 `:415-416` 核实 Windows Ctrl+E / Ctrl+B 的 Extrude / Bevel 入口；
  仍需逐项核对 Blender 操作模式和参数，不在本次文档提交中启用。

只记录功能身份、路径、输入与行为证据，不复制 Autodesk 的实现代码、算法或个人配置。

每条接入记录必须包含：来源位置、Maya 默认输入与路径、适用上下文、分类、
AxisMeld ID、Blender 对应入口、交互类型、参数入口、差异、自动化证据与手测状态。
每条 Maya 缺失项还须有唯一计划编号、缺失能力、依赖和验收目标；不能仅写“以后开发”。

## 7. 验收与交付

1. 静态与配置：命令身份一致、无重复绑定、未知命令拒绝、占位不可执行、旧配置兼容。
2. 原生事件：点按、按住、自动重复、连续拖选、菜单穿越、鼠标/键盘两种释放顺序、
   Esc、失焦、区域尺寸改变与取消后鼠标原地 W/E/R。
3. 上下文：Object、Mesh Edit 点/边/面、空选择、多对象编辑、隐藏/不可选对象、
   单/四视图、非目标模式、文本输入和 UV 不被改键。
4. 命令结果：真实选择/几何结果、持续工具身份、确认/取消、一次撤销、Recent 状态。
5. 交付：更新现有测试入口，不新增整套 build；保留回退版和个人配置。
6. 集中手测表按批次列出“已实现待手测 / 未实现占位 / 已知差异”，自动化通过不等于 Maya 手感一致。
