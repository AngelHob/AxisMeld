# Phase 2A：Space 热盒入口与视图切换

日期：2026-09-09。性质：新交互子系统的开发规格。
状态：四项范围已确认；用户在搁置缩放专题后要求继续其他开发，按本规格进入实施计划与开发。

## 1. 本批交付范围

仅在 AxisMeld Maya 2026 预设、3D View 的 WINDOW 区域、Object 或 mesh Edit Mode 生效。
不要求选中对象，空场景也能使用。交付：

1. 短按 Space，在单视图和四视图之间切换；从四视图进入单视图时保留鼠标所在面板。
2. 按住 Space 显示热盒入口；释放关闭，菜单操作不误触短按布局切换。
3. 热盒中心方向菜单提供透视、侧、前、顶视图切换。
4. 四个面板的视角、观察中心和缩放在本会话的放大/恢复过程中保持独立。

这是视图热盒的首个切片，不宣称完整 Maya 热盒对等。完整菜单行、其他热盒区域、
建模菜单、UV、摄像机对象管理、临时吸附与变换数学均不进入本批。
AXM-COMPAT-001 Global 缩放保留原生行为，用户试用 Maya 后决定无需开发，不启用实验替代路径。

## 2. 依据、已知差异与方案选择

当前项目中 Space 仍在 `commands.py` 的 RESERVED_KEYS；原有语义命令不支持热盒。
`screen_ops.cc::region_quadview_exec` 在退出锁定正交区域时可能换用用户视图，
并移除其他区域；重新进入时又重新初始化标准方向。因此只重绑该 operator 不满足视角恢复契约。

Maya 2026 参考：

- 官方 [hotBox 命令](https://help.autodesk.com/cloudhelp/2026/ENU/Maya-Tech-Docs/CommandsPython/hotBox.html)
  区分调用、释放与 noClickDelay；短按定位使用按下时的指针位置。
- 官方 [marking menu 说明](https://help.autodesk.com/cloudhelp/2026/ENU/Maya-Basics/files/GUID-8BA1A3AA-4C44-4779-8B22-0AAE3627E8EB.htm)
  支持按键配合鼠标、按方向快速拖动。
- 本机原版 Maya 2026 `HotboxMenus.mel` 将短按阈值配置为 0.4 秒，
  不同于 hotBox API 文档所列的底层默认 0.1 秒。
- 本机 `HotboxCenterMenu.mel` 的四个主方向为上透视、右侧、下前、左顶。
  只提取行为事实，AxisMeld 不复制或分发 Autodesk 实现代码、菜单资源或图标。

方案比较：

| 方案 | 优点 | 局限 | 本批选择 |
| --- | --- | --- | --- |
| Python modal + 原生四视图开关 | 初版接入少 | 视角恢复和生命周期仍需补齐；每次输入进入 Python | 不选为正式事件核心 |
| 独立原生状态机 + 窄区域接口 + 内置命令配置 | 输入/绘制生命周期可控，核心改动集中，复用 Blender 区域 | 需要少量原生接缝和回归测试 | 采用 |
| 自建四个编辑器或重写窗口布局系统 | 控制范围大 | 影响工作区、布局和上游合并，超过本批范围 | 不采用 |

本批沿用 Blender 的 Z-up 场景及标准前/顶/侧方向，不旋转世界或模型。
仅提供四个主方向，不包含 Maya 的左、后、底或完整菜单行；状态标为 adapted。

## 3. Space 与鼠标交互契约

短按判定默认 **0.4 秒**，可在预设偏好中调整（0.1–1.0 秒）；公共默认和用户设置分离。
该阈值用于判断是否切布局，不是强制等待菜单响应的延时。按下后即可绘制中心入口，
Space+鼠标的快速手势无需等待；短按过程中入口可能短暂出现，这是明确的显示取舍。

按下时记录当前窗口、编辑器区域、子视图及原始指针位置，之后不随悬停切换目标面板。
计时使用单调时钟，不用帧数或键盘自动重复计数。

| 当前状态/事件 | 行为 |
| --- | --- |
| Idle + 触发键按下 | 进入 Pending；记录上下文和时间，安装绘制/必要计时器 |
| Pending + 触发键自动重复 | 忽略，不重启计时，不创建第二个操作 |
| Pending + 未发生菜单交互，提前释放 | 清理热盒后切换一次布局 |
| Pending + 达到阈值 | 进入 Held；之后释放不得触发布局切换 |
| Pending/Held + 中心区 LMB 按下 | 立即进入 Marking，锁定手势原点，永久取消本次短按资格 |
| Marking + LMB 拖动 | 根据方向高亮目标；中心死区不选中命令 |
| Marking + LMB 释放到有效方向 | 执行一次视图命令，回到 Held；Space 仍按住时入口保留 |
| Marking + LMB 在死区释放 | 不执行命令，回到 Held；不切布局 |
| Held/Marking + Space 释放 | 关闭；尚未释放鼠标的候选命令取消，不隐式提交 |
| 任意活动状态 + Esc | 取消候选，清理；此前已执行的视角切换不回滚 |
| 任意活动状态 + 失焦/源区域消失/预设或模式改变 | 安全取消，不执行布局或菜单命令 |

原点附近的中心死区为 12 个逻辑像素；菜单高亮与命中计算使用同一坐标与 UI 缩放。
四个扇区保持固定：上透视、右侧、下前、左顶；距离不限于可见按钮边框，支持快速划选。
精确落在对角分界时不选命令，避免抖动时任意切向。
首批采用中心 LMB 按住拖动后释放的操作；点击松手再选择、MMB/RMB 的区域菜单后续补齐。

热盒期间不穿透鼠标事件去选择、变换模型或 Alt 导航；关闭后原有行为立即恢复。
不抢占其他编辑器、文本输入、其他 modal 工具的输入。
取消后若触发键仍按住，忽略其自动重复；必须经历释放再按下才能开启新一轮。
窗口重新激活时也采用同样的重新按键保护，避免遗失 RELEASE 后热盒粘住。

## 4. 单视图/四视图状态

缓存属于当前 View3D 空间的运行时，不能由全局“最后一个视图”变量共享。
每个面板有稳定的逻辑槽位；缓存仅记录可恢复的视图数值，不持有将被销毁的 ARegion 指针。

- 首次从单视图进入四视图：上左顶、上右透视、下左前、下右侧。
  原单视图为标准正交方向时保留到对应槽位；用户视图保留到透视/用户槽位，
  不强制改掉原有正交投影。其余槽位沿用当前观察中心和距离初始化。
- 四视图短按：保存四个槽位，单独显示按下 Space 时指针所在槽位。
  不调用会替换成用户透视视角的默认退出行为而不加补偿。
- 再短按恢复：把单视图期间的导航/视角切换写回该槽位，其余三个槽位恢复原值。
- 同一个槽位通过热盒改成其他方向，不改变它的槽位身份。
- 切透视时优先恢复该槽位最近一次透视姿态；首次无记录时使用当前朝向和观察中心切为透视。
  切前/顶/侧时使用 Blender 标准方向，保留当前观察中心和距离，不自动 Frame All。
- 视图切换不改变几何、选择、对象模式，不新增几何 undo 步骤。

数值快照覆盖旋转四元数、中心、距离、投影/标准方向/轴滚转、四视图锁定状态及相关历史视角。
保留现有 View3D 共用的 lens/clipping/shading，不伪造每个子面板独立镜头配置。
四视图期间的联动锁定标志也要恢复；单视图显示时解除四视图专属锁定，恢复时还原。
区域缩放只重新计算绘制布局，不重置快照。

运行时快照不新增 `.blend` 持久化字段。关闭文件或重启后，只有 Blender 原生保存的
当前布局/视图存在；若以单视图保存，不能承诺恢复未写入文件的其他三个槽位。
销毁、复制或读入 View3D 时必须释放或清空快照，禁止悬空指针和跨空间串用。
手工改动区域结构、撤销导致上下文重建或切换场景时，使旧快照失效；重新建立安全布局。

首批不在 Local View、摄像机锁定视图或 XR 中切换布局；须在修改区域前提示不支持并退出，
不能清除摄像机关系或修改摄像机对象。普通四视图锁定正交面板属于支持范围。

## 5. 模块和接口边界

### 5.1 输入与绘制

- `source/blender/axismeld/AXM_hotbox_state.hh`：不依赖 UI 的状态转移、时间/重复键判定及方向命中。
- `source/blender/editors/space_view3d/view3d_axismeld_hotbox.cc`：原生 modal operator、区域绘制、
  计时器和清理；每次完整手势才调用一次语义命令，不在鼠标移动中调用 Python。
- 绘制为原生区域覆盖层，只显示 AxisMeld 中心入口和四向文字/高亮。
  不新增永久工具栏，不调用独立弹窗遮断按键释放，不加载外部字体或品牌素材。
- 所有退出分支移除计时器/绘制回调并重绘；命令执行失败报告原因，不转为短按动作。

### 5.2 视图状态与原生接缝

- `view3d_axismeld_views.cc` 管理数值快照、逻辑槽位和视角命令。
- 在 `screen_ops.cc` 暴露最小四视图切换接缝：允许 AxisMeld 保留指定子视图，
  默认原生 operator 的行为不变，不复制一整套区域创建/销毁代码。
- 在 `View3D_Runtime` 增加专用运行时快照所有权入口；不借用 N 面板的 properties_storage。
  在 `space_view3d.cc` 的 free/duplicate/read 生命周期处理释放与重置。
  即使声明所在文件是 DNA header，也不把快照当作新的可保存场景数据。
- 不修改 GHOST、全局窗口消息分发或对象/网格数据结构。

### 5.3 命令与配置

- 添加 `hotbox.open`（默认 Space）、`view.toggle_quad` 及四个视角语义命令。
- 命令元数据允许“无独立快捷键”的菜单命令；仅有键位的命令进入 baseline_bindings。
  保持现有用户 JSON 的 schema_version=1 可读，不要求用户迁移旧文件。
- 触发按键记录实际 invoke event，释放同一键结束，不硬编码 Space RELEASE。
  本批 hotbox.open 只接受键盘触发；无效覆盖按原有配置层错误处理回退，不覆盖文件。
- 在预设配置层提供短按阈值；生成键位时只调整建模 3D 区域，不修改全局 Frames/Screen 键表。
- 对新增默认 Space 做全局冲突检查；遇到真实冲突先定位归属，不静默删除上游全局快捷键。

实施前验证发现：视口内部 Frames handler 早于普通 3D View handler，Space 会先播放动画。
因此增加仅注册在 3D WINDOW 区域、Frames 前的 `AxisMeld Hotbox` 键表，默认只由本预设填充，
operator 仍检查模式与预设。仅对此入口与原版 `Frames/screen.animation_play` 的 Space 冲突作明确豁免；
其他全局冲突照常拒绝。独立事件实验确认前置区域处理可拦截 Space，时间轴及禁用后的播放行为保留；
正式新增入口仍须通过产品事件测试。

## 6. 验收门槛

| 编号 | 验收内容 |
| --- | --- |
| H1 | 短按只切一次；自动重复不重启计时；阈值前后及刚好阈值有确定结果（等于阈值算长按） |
| H2 | 长按不切布局；快速 Space+LMB 手势无需等待；释放鼠标提交一次，释放 Space 不重复提交 |
| H3 | 四个主方向命中正确，死区/对角分界不误选；UI 缩放和窗口边缘命中与高亮一致 |
| H4 | 四个面板分别放大后仍保留自身方向；单视图导航后恢复只更新该槽位 |
| H5 | 重复往返 20 次无视角漂移；两个 3D 编辑器及两个窗口不串用状态 |
| H6 | Esc、失焦、区域关闭、预设/模式切换清理回调；重新进入可用，不吞后续输入 |
| H7 | 无选中对象仍可用；对象几何、选择及几何 undo 不变；其他预设/编辑器和已有 W/E/R 行为不回归 |
| H8 | Space 用户重绑定/禁用、旧配置加载、冲突诊断正常；不写用户个人配置 |
| H9 | 不支持的 Local View/摄像机锁定/XR 上下文在修改布局前退出；场景相机不变 |
| H10 | 当前布局保存重开正常；关闭/复制空间无崩溃；不宣称跨重启保存隐藏槽位 |

先写纯状态与配置测试，再以独立隐藏 GUI 进程回放真实输入，断言 region 数量、
viewquat/ofs/dist、命令计数及几何未变。GUI fixture 必须使用私有 TEMP/TMP/TMPDIR、
BLENDER_USER_CONFIG 和退出快照目录，禁止注入用户正在使用的进程。
只有 GUI 事件通过才能交付手测；“纯状态测试通过”不等于热盒已可用。

计时区分输入状态判定、命令耗时和实际显示延迟，不凭数值测试宣称此前卡顿已修复。
只构建受影响目标后安装，运行既有 AxisMeld 回归与新测试；沿用独立审查门槛，未取得审查结论
不得自行将本地开发视为已批准集成。全局缩放延期不解除阶段 1.1 的待审状态。

## 7. 自审结论与下一步

本文已明确短按边界、快速手势、首次布局、视角缓存生命周期、保存边界、配置兼容与非目标。
具体实现不允许把暂时拿不到的上下文退回“最后一个活跃视图”；应安全取消。
本机 Maya 脚本和官方文档仅支持上述记录的行为事实，不视为完整鼠标交互验收。

按用户继续开发的指示编写分任务实施计划；原生输入/绘制、四视图恢复及配置测试分别设检查点。
本规格不代表代码已经实现，也不授权上传或发布。
