# 中心鼠标映射列表预检（尚未实施）

五小时批次的第二候选切片。先等待短设置列表完成 GUI 验证与审查，再据实际结果制定实现计划。
这份预检不代表映射列表已经改成原生菜单。

## 现场实现

- `scripts/modules/axismeld/hotbox_catalog.py`：Center Mouse Buttons 下有左/中/右三个子目录，
  每个目录包含同一组 13 个设置选项，包含 Disabled、Views、Recent、Controls 及各普通目录。
- `hotbox_menu.cc`：当前只有短设置列表使用连续原生布局；普通目录采用最多 8 项的分页椭圆，
  通过 `@scroll:<owner>:previous/next` 使用每个 owner 的 offset。长映射选项尚未原生化。
- `view3d_axismeld_hotbox.cc`：翻页控件在按下时执行，release 被 navigation_consumed 吞掉；
  滚轮按实际 hover 所属目录滚动，离开子级会清理该目录后面的 open_path。
- `axismeld_hotbox_menu_events.py`：已有真实 UI 测试通过右键映射目录选择 Pane Shading，
  同时断言 runtime 值和只包含该覆盖项的 user JSON；后续必须保留这些结果断言。

## 下个设计需要明确的边界

1. 13 × 24 逻辑像素的完整列表在窄窗放不下。优先保留字体和目标高度，增加连续菜单内
   的上下滚动入口；复用 offset 与导航所有权，不增加独立弹窗输入处理器。
2. 正常尺寸应显示全部选项，不为了保持分页而强制限为 8 项；不足时才滚动。
3. 每页仍需可辨识的上下导航和 disabled 边界；所有 13 项必须可达，滚轮不能操作场景。
   不接受丢选项、缩小点击目标或者无限增高出界。
4. 三级“鼠标键选择”也属于设置目录，应评估连续原生菜单，而不是仅把最终叶子改成列表。
   但短列表当前按 Menu-kind 分开画背景的规则不能直接照搬：原生列表内部的 submenu 项应
   共享背景，热盒上的分离入口才需要独立背景。必须先设计和测试这个分组区别。
5. 保持父级显示、至少 10px 的入口分隔；深层菜单不得遮住直接入口。窄窗需要测试链式
   回退，真正容纳不下时显式 unsupported，不采用错误命中区域。
6. 必须覆盖点击、按住划选、滚动后选择、取消、Space、非拥有鼠标松键、文件保存和重启。
   默认鼠标映射与用户已有文件不改变，只改变浏览容器。

## 不做

不引入新设置 schema、不增删映射选项、不改默认键位、不修复跨窗口 guard。
若需要新的全局输入架构才能安全落地，则记录阻碍并转做已授权的其他局部工作。

## 局部方案（已形成后续计划，尚未实施）

- 显式分类四个内置目录：Center Mouse Buttons 与 Left/Middle/Right Mouse Button。
  前者是三个带子菜单箭头的原生行；后三者是 13 个设置叶子的原生行。不得按字符串任意
  后代匹配，把其它目录无意改成列表。
- 正常尺寸显示全 13 项；仅映射叶子列表在容量不足时使用同一列表内上下各一个 24px
  导航行，中间至少一个选项。边界导航灰显；滚动步长复用现有一项 offset，当前目录独立保存。
  首尾控制常驻有助于滚动时保持列表位置稳定。较短的现有 Style/Rows/Transparency 不增分页。
- 优先右侧，其次左侧，再沿用上下避让直接入口的规则；若完整列表无法避让，才逐步降低
  映射页容量并试放。不得仅按视口总高度计算容量后覆盖入口。
- 绘制需要分清“热盒上的独立原生入口”和“连续列表内的子菜单行”。候选是在 MenuRect
  追加一个默认 false 的独立入口标记，由 ellipse 布局赋值；renderer 依据标记分块，
  仍依据 node.kind 画子菜单箭头。它只属于 C++ 布局结果，不新增 Python JSON 字段或输入状态。
  这比按像素相邻推测分组更明确，也避免 renderer 再维护一份目录 ID 白名单。
- 导航 ID 继续使用 @scroll；原生竖列表使用 Blender 的上下三角图标，椭圆旧导航保持原样。
  draw-only 适配器追加默认无图标的 icon-only 参数，仅用于这两个导航行；避免将普通映射
  选项已有图标误当作整行内容，所有设置文字仍保留。
  初版是有明确入口的滚动列表，不承诺 Blender 原生自动悬停滚动或键盘焦点行为。

待落地的验证应覆盖全 13 项、首页/尾页和陈旧 offset、三个鼠标键独立设置、深层菜单
连续背景、真实窄窗与 2x 四视窗、滚轮/导航点击及 release 不误触设置、保存/重启和原热盒回归。

具体实现边界见 [映射列表计划](../superpowers/plans/2026-09-11-hotbox-mapping-lists.md)。
此处的两项 C++ 附加标记不涉及 JSON、用户设置或输入状态机；若真实验证需要超出这些局部
接口，则先报告证据与取舍，不自动扩展成全局菜单机制。
