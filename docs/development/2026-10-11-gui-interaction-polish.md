# 建模灰项与热盒重复唤出交互修复

日期：2026-10-11。基线：`00a2655c109f48a20d72733a2eb0ce4d0f61dd3b`，窄范围拉取确认与远端一致。

用户要求继续修复剩余菜单和热盒交互，并同步源码、修改日志与公开待测内容。本批延续已有 UI/输入约定，不新增建模或绑定算法。

## 已定位的路径与复现门禁

1. Modeling 原生分组不符合视窗、模式或对象条件时，仅将布局设为 disabled；动态分组退化为没有说明的 label，其余分组仍创建真实子菜单。无活动对象时，灰色 Extrude 子菜单的原生 draw 会访问 `context.object.data`。需在真实 GUI 中核验无原因提示和不安全子菜单预览。
2. 工具热盒 `rearm_tool()` 清理主路径却保留 `companion_path`；下一次同一工具的 LMB stroke 仍接受上次的伴随子菜单路径。需验证 W/E/R 保持按下、进入 Selection Constraints 后松开 LMB，再次 LMB 唤出是否残留旧级联。

只有复现确认后才修改对应生产路径；现有测试失败先区分测试前提与产品缺陷，保留失败回执。

旧 menu-preview 已在实际 GUI 复现第二条：W 保持按下，进入 Selection Constraints 的 UV Edge Loop 后松开 LMB，再换位置按 LMB，旧 UV Edge Loop 文字仍完整可见，伴随菜单由根的一列变成两列。失败回执为 `repost-red`；场景和选区不变。

第一条也已在旧候选实际界面确认：无活动对象的 Control Points 灰标签没有原因提示；悬停分类目录里的灰 Extrude 后，真实原生 draw 抛出 `NoneType.data`，并调用了不适用模式的原生扩展回调。失败证据为 `modeling-red-3`。早期测试误选同名 Maya Extrude、将顶栏文字误认作 tooltip 和默认工作区仍处于 Edit Mode 的前提错误已区分，不属于产品缺陷。

## 修复约定

- 不满足分组前提的 Modeling 原生入口保持灰色，悬停解释所需模式、对象或视窗；不创建依赖缺失上下文的原生子菜单预览。已满足分组前提时继续走真实原生 Menu/operator，保留原生 poll、参数、插件回调和资产入口。不能隐式选对象或切换模式来变成可用。
- 每次工具热盒的 LMB stroke 结束后，伴随菜单的临时路径与主路径一起复位；同一个 W/E/R 持键会话中的下次唤出从根目录开始。保留一次 stroke 内的父子导航、原点取消、真实命令执行和重复唤出规则。
- 保留四视图布局标杆、完整展开、底部对齐及现有窄窗口说明。保留 Modeling 七根与独立 Options，不增加滚动、折叠或删除灰占位。
