# 自定义属性参数窗口修复

日期：2026-10-29。接续用户“继续开发”的 UI/交互授权，修复现有功能，不引入新算法。

## 事实与方案

当前 Space → Modify → Add Attribute... / Edit Attribute... / Delete Attribute... 使用 `AXISMELD_OT_m3_custom_property`。独立 Blender 5.4 探针确认：编辑整数直接确认会变为浮点；布尔值按浮点解析报错；Property 下拉切换不刷新字段；首次确认前活动对象变化时可能把草稿写入另一对象。现有自动检查只覆盖 EXEC_DEFAULT 显式参数，未覆盖 invoke 和下拉更新。探针使用实际原生属性及原方法、替身对话框宿主，不算物理 UI 验收。

采用修复现有原生参数窗：初始化/切换时从目标属性同步草稿，首次确认核对来源。相比复制整套 Options 窗口或新增 Apply/Reset 常驻控件，此方案直接覆盖已确认缺陷，保持用户现有操作习惯。该实施选择由开发者根据已批准 UI 范围确定。

## 行为约定

- EDIT/DELETE 打开时选取当前对象已有可支持属性；EDIT 的名称、类型和值必须来自同一属性。支持 FLOAT、INTEGER、BOOLEAN、STRING，bool 先于 int 判别；字符串和用户自定义属性名不翻译。ADD 保留现有默认值。
- EDIT 在 Property 下拉选择另一项时重载该项名称、类型和值；这是明确换编辑目标，未确认的上一项草稿不写入对象。打开、切换和取消都不写场景数据。DELETE 删除所选项，不误用旧名称。
- 用户仍可明确修改值、类型或名称，原生 operator 的显式 EXEC_DEFAULT 参数保持有效；回调只在实际打开的对话框草稿期间同步，不覆盖脚本/菜单传入的参数，也不破坏 F9 重算参数。
- 对话框只允许写回首次打开时的窗口、场景、View Layer、活动对象及模式；失效、换对象、换来源、属性被删除/变成不支持类型时取消并给出双语原因，不自动改选区、模式、布局或寻找替代目标。保存稳定身份，不持有可能失效的借用 RNA 指针。
- 首次确认成功后释放临时对话框保护，保持原生一次 Undo/Redo/F9 行为；F9 因 Undo 重建 ID 不应误判。已有名称冲突/无效值的拒绝规则保留，失败不修改属性。
- 保留 Blender 全局栏、Modeling 七根、Rigging 两根、灰占位、四视图标杆间隔和 18px 伴随列表。无新快捷键、新菜单、持久化设置或自定义属性复杂类型扩展。

## 验收与交付

针对性回归先证明旧行为失败，再覆盖四类型无改确认、下拉切换、取消不写、显式 EXEC 参数、来源变化/目标失效、无效值及命名冲突。隔离真实 Blender GUI 验证实际对话框确认/取消与原生 Undo/F9，区分模拟事件和人工操作；双语及高 DPI 完整可读性仍登记人工待测。
