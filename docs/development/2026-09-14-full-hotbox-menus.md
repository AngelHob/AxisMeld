# 热盒菜单完整展开与底部对齐

## 用户要求

2026-09-14：热盒菜单不要折叠和滚动；下方不足以显示完整 UI 时参考 Maya 底部对齐。此前已明确菜单内容必须对齐 Maya，不能删除未实现项来减少高度，五行热盒的间距继续以 Views 为基准。

## 实现约束

1. 当前打开目录的所有直接子项一次显示，保留顺序、分隔、图标、状态、Options 和真实子菜单。取消空间不足导致的分页、上下箭头、人工 Back 页及滚轮换页；鼠标滚轮在菜单期间仍被消费。
2. 伴随菜单保持热盒上方、列表下方的组合。下方不足而完整组合可容纳时，对整个组合及其命中、返回、空白、遮挡区域统一上移，底部对齐显示区域的安全边界，不侧翻整个伴随列表。
3. 显示表面与操作来源分离：允许在同一个 Blender 窗口内跨四视图窗格显示，操作仍作用于调用时捕获的视图、对象及选集。窗口销毁、区域改变和取消继续清理回调与输入所有权。
4. 整个窗口也容纳不下完整单列时，按原顺序分列显示，尽量在分隔处换列。行高 24、分隔 6、字体、图标及 Views 净距不缩小；每个条目恰好出现一次。列和级联均参与完整命中与遮挡，不允许透过列表划选。
5. 第 3/4 条是针对物理尺寸边界的建议默认，已向用户询问可选偏好；若用户回复则更新。曾使用 Display 56 个同级节点推定常见窗口需要分列；用户指出该层级不符合 Maya，已撤回此内容假设。先按 `2026-09-14-maya-complete-menu-hierarchy.md` 核对真实树；容量测试另用明确的合成目录。
6. 真实按下位置不伪造或平移。显示中心、方向与返回区域使用最终布局；鼠标捕获、目标拾取与取消语义单独验证。

## 验证与交付

- 原候选实机复现中低位置分页及极低位置侧翻，保留真实 PASS/FAIL 日志，不把未复现的测试称为 RED。
- 原生测试验证完整清单、无分页、底边对齐、整组平移、Views 净距、分列、参数格、深层级联、边界尺寸和命中区域。
- 实机验证 Object、Create、Component、Face、QWER、Space 深目录；单视图/四视图、1x/2x、跨窗格显示与原区域执行、滚轮不穿透、重复唤出及取消。
- 独立新安装目录，保护以前构建及用户配置；人工测试追加到统一清单和私人网页，保留历史已测记录及在线进度。

## 不变的内容边界

“不折叠”指不要为适配空间隐藏条目，不代表同时展开整个递归菜单树。真实 Maya 子菜单保留。极端到整窗宽高均无法容纳所有固定尺寸列时必须报告明确边界，不截断条目或误执行不可见操作。

## 绘制与输入约束

跨窗格采用窗口绘制回调和临时绘制区域，事件及命令上下文仍归调用时的源区域。临时区域不注册进真实界面，不用于执行命令；关闭窗口、区域失效和缩放变化时清理回调、临时上下文与 GPU 资源。

窗口默认缓冲与原视口 sRGB overlay 的混合方式不同。直接改用窗口缓冲曾使未选中单选圆圈的最高 RGB 从 166 降为 128；恢复主题不足以修复。完整菜单需保留原生 sRGB 混合路径，并通过原有单选、透明度和图标像素断言验证，不提高单个图标颜色或降低验收阈值。

布局移动后，测试按实际渲染定位环与列表，同时保留真实按下点、方向动作、取消、撤销和 Views 内缘断言。菜单打开覆盖鼠标位置时，用可执行叶条目的阳性对照验证首次原地释放保护；不可达的悬停路径不能作为误执行缺陷的证据。
