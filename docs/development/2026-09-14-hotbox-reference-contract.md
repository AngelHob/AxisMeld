# 四视图热盒布局标杆与回归约束

2026-09-14，用户报告五行热盒第2/4行及第3行左右间隔过窄并明确要求以四视图热盒为标杆。此约束覆盖QWER及子环、组件RMB、创建Shift+RMB、Space路径和后续新方向热盒。

## 已确认的错误

77844b7582e只把工具的side加量从32换成Views使用的8，但工具popup仍把中心宽度固定为24。对于共用公式，2/4行的左右净距是中心宽度减16（实际8），3行是中心宽度加16（实际40）。Views中心宽度来自实际AxisMeld标题加主按钮padding40，因而净距更宽。共用函数与常量没有保证实际间隔一致。

旧测试以中心附近±10/±24命中为正确结果，证明的是过短划选距离，未比较四视图。单纯“矩形没有重叠”和自动化通过不足以证明误触风险已消除。

## 修复契约

1. 四视图现有布局为参考，不缩小四视图去匹配其他菜单。
2. 同一字体测量下，通用radial的2/4行与3行左右内缘距离直接对齐Views；以`views`实际标题宽度加主按钮padding40作为中心宽度，标签仍各自保留完整宽度。
3. 缺席方向、夹紧、中心返回/取消与外延命中使用相同基准。间隔不能只有视觉空白而仍从内部误命中邻项。
4. 保留既有五行、24高次级按钮、QWER持键重复唤出和父子返回行为。此缺陷只修复横向留白，不擅自重排方向或缩小目标来适配狭窄视口。
5. 每次涉及热盒布局的改动必须把Views与至少QWER、组件、创建、深层radial作直接对照，覆盖不同label宽度、边缘夹紧、单/四视图、内侧空白、外延及缺席方向。测试不能只复制实现公式或用“能点中”代替比较。

## 后续实现与验收

布局修复先通过独立几何RED/GREEN与实际GUI，再开始M3功能接入。M3目录和设置继续用原生列表；新增方向热盒必须遵守此契约。最终人工清单合并原G/K项与新布局、M3项，旧用户反馈保留，自动化不代替用户次日的手感验收。
