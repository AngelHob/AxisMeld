## 现象与证据

旋转过的网格在 Object Mode 下沿 Global 单轴缩放，外形可能不等价于严格沿世界坐标轴缩放。
例如绕 Z 旋转 45 度的立方体，Global X 放大两倍时，原生路径将自身 X/Y 缩放都变为约 1.58114。
相同目标在网格 Edit Mode 下可以直接作用于顶点；这不表示两种模式的操作语义等价。

2026-09-09 独立技术验证确认：

- 直接赋值对象世界矩阵仍会分解，不能消除此差异。
- 父级逆矩阵补偿能精确表达初始缩放，但后续原生旋转出现偏差，不采用透明补偿。
- 几何节点或直接几何变换存在不同的修改器、层级和共享数据边界，均未进入产品。
- 本机 Maya 2026 的世界空间 scale 命令会提示将非物体空间缩放烘焙到组件；
  不能把“必须增加对象剪切属性”作为对齐 Maya 的已确认前提。该验证为命令级，不是完整操纵器验收。

上述结论仅用于后期设计，当前构建仍保留原生行为。点选轴、中键拖动通过事件测试，
不等于坐标系数学已与 Maya 对齐。此前未旋转网格的缩放测试不能覆盖此差异。

## 历史设计讨论：基础几何优先（2026-09-09，非待实施承诺）

用户明确选择：**先按世界轴缩放基础几何，再按原顺序和当前参数计算修改器栈**。
不是把已经经过修改器的最终显示几何整体拉伸；不自动应用、重排或改写修改器参数。
例如 Bevel 应在变化后的基础形状上重新计算，而不是拉伸上一次倒角产生的外形。

因此，原实验中“基础几何变换后再 Bevel”与“先 Bevel 再整体变换”的差异，
是两种目标的区别，不是当前已选顺序下的失败。原测量保留，但其最终外形对照
不能作为后期实现的验收判据，也不能据此一概排除带修改器对象。

后期测试应分别验证基础顶点的世界轴变换，以及修改器在该基础几何上的正常重算。
共享网格、子物体范围、形态键、动画与高面数交互仍需各自明确策略并验证。
这一讨论只澄清计算顺序；随后用户试用 Maya 并决定无需开发。本节仅保留背景，不是待实施任务。
