# 热盒与普通菜单的组合规范

用户于 2026-09-10 明确要求长期采用此规范，后续会有多处同类设计。

- **热盒**用于方向明确、适合肌肉记忆的快速操作，例如视图切换。
- **Blender 原生普通菜单**用于设置、选项列表及需要逐级浏览的目录，例如 Hotbox Style。
- 两者可以组合与级联；不要把全部子级都画成环形／椭圆按钮，也不要把普通选项画成分散的大卡片。
- 普通菜单继承 Blender 的背景、连续菜单项、字体、悬停高亮和禁用样式，复用原生组件。
- 父级热盒保持显示；子级活动时避免输入穿透。按键所有权、松键返回、Space 关闭与取消必须统一。
- 主热盒与二级热盒的尺寸独立；缩小二级按钮不等于缩小字体，也不压缩一级中央安全留白。
- 未实现功能仍保留灰显占位，不用可点击空操作冒充已接入功能。

新交互应先决定内容属于哪一类，再选择容器；不能仅按菜单层级决定一律使用热盒。

## 2026-09-11 用户确认的修正

- 二级及更深的椭圆热盒使用更醒目的中灰底，文字、高亮、禁用样式继续跟随Blender主题；普通菜单不改色。
- 普通菜单与直接入口/父菜单贴边放置（间距0），左右不够时上下贴边；一级中央留白和椭圆内部4px间距不变。
- 普通子菜单打开时，保留背景热盒的显示，但无关热盒入口不再参与命中；当前路径入口、普通菜单兄弟项及Back仍可操作。
- 回归必须包含逐步鼠标拖曳穿过背景入口，而非只把鼠标瞬移到子项；验证真实设置结果、取消/释放和后续W/E/R。
- Alt旋转中Shift吸附暂不修改公共默认。选择上下文与Face Step语义获认可，不扩大为全部人工测试通过。

### 同组等宽与菜单入口同色（用户追加确认）

- 同组椭圆动作按钮按最长标签及必要内边距等宽，整个新增宽度均参与命中；不缩小字号和24px高度。
- 普通二级目录中的同组菜单入口也等宽；Views下方Hotbox Style仍保留独立菜单入口和箭头，不改变为方向动作。
- 热盒上的独立原生菜单入口与椭圆按钮共用中灰底及透明度；展开后的连续菜单仍用Blender原生菜单背景。
- 保持4px椭圆间距、一级中央留白、原生级联贴边和背景输入隔离。窄窗优先沿用短视图标签，不以不等宽挤入。

### 默认样式与分层透明度（用户最新确认，取代上述灰底方案）

- 一级热盒默认75%透明度（背景25%不透明），文字/图标不随背景变淡；Transparency设置仅作用于一级。
- 二级及更深的热盒动作、独立菜单入口和连续菜单恢复Blender主题配色、边框和高亮，背景完全不透明，不再使用自定义中灰或继承一级透明度。
- 菜单不透明只作用于这些临时绘制组件，不修改Blender全局主题；包括主题菜单背景自身带透明度时也保证不透出场景。
- 保留等宽、椭圆布局、原生菜单箭头、紧凑间距和输入/取消行为。已存在的个人透明度覆盖优先于新默认，不迁移覆盖个人文件。
