## Approved interaction contract

- Main hotbox: aim for 38 logical-pixel buttons (previous 28), 10-pixel separation (previous 4), generous horizontal padding, natural text widths. Keep the overall horizontal oval and Blender native font/theme/icon style. Values are AxisMeld tuning, not measured Autodesk parameters.
- Central seven-view marking menu: true horizontal ellipse, not a 3x3 grid. Keep existing semantic directions and empty NE direction. Use a usable center dead zone and direction-based marking rather than requiring precision hits on text; no cursor warping or secretly changed gesture origin.
- Other secondary menus: elliptical arrangement too, with bounded grouping/paging for long menus. Keep all commands, disabled reasons, nested navigation, setting/Recent behavior and per-owner page state. Do not squeeze buttons to fit. At viewport edges and in quad panes, keep accessible sizes, no overlap or clipped labels; prefer safe inward placement and paging.
- Visible clickable buttons and hit geometry must agree. Do not change mouse ownership, key release cleanup, default direction assignments, or introduce hover-triggered command execution. Keep native hot-path computation; no Python pointer-motion calls.
- Secondary navigation refinement from validation: render/hit only the active ring, with its center returning to the parent path/page. Empty ring space must not fall through to hidden roots or restart center-only mapping. Immediate page/back presses own their matching release even if re-layout changes the button underneath. Latched menus use explicit clicks to enter a submenu; while a button is held, hover traversal and leaf-release selection remain available.
- Inward-clamped marking labels remain real targets: the press-origin dead zone cancels first; outside it, a hit on a visible view label selects/highlights that label's view. Uncovered space still uses the seven original directions from the actual press origin, with NE empty. This reconciles readable inward placement with visible-hit consistency without moving the cursor or changing the gesture origin.
- The center Style entry must be transparent to an ongoing original seven-view marking gesture: no hover-open, hover highlight, or widened effective dead zone while the pointer takes small steps out of the origin. The 12-pixel dead zone and view direction still apply over this center decoration. After a neutral release, a fresh explicit Style click can enter its menu; ordinary title-held drag into a Style setting remains available. This boundary is verified with multi-sample movement rather than only one large synthetic jump.
- Fixed front/top/side/back/left/bottom orthographic views must not tumble with Alt+LMB, including a maximized fixed pane. Pan and dolly remain available. An explicit switch to Perspective restores free tumble. Only AxisMeld preset navigation is in scope; do not lock arbitrary user orthographic views, actual scene-camera transforms, or other presets by accident. Preserve quad pose/BOXCLIP ownership and the accepted W/E/R behavior.

View-lock diagnosis: the previous maximization path explicitly clears `RV3D_LOCK_ROTATION`, and explicit axis actions only set pose/projection. Real old-stage Alt+LMB passes the quad pane but changes its maximized view (view-lock-red.log). Set the native rotation-lock bit in AxisMeld fixed-axis actions, preserve it on maximizing, clear it on explicit Perspective, and preserve quad-only BOXVIEW/BOXCLIP independently from the current projection's rotation lock. This changes native view state chosen through AxisMeld actions, not other presets' navigation rules; existing explicit view state/locks are not silently reset merely by switching presets.
